# Surface-water re-evaluation — frozen protocol (approved by the author, 14 Oct 2026)

**Primary target: surface water, as in Sen1Floods11.** Every water pixel counts, permanent water included.
- WorldFloods-v2 test: gt water (flood + permanent) = water, land = land; cloud, invalid and all-zero spectrum ignored. Windows: 512 px native tiling, partial windows zero-padded (revision P3 geometry), kept if > 1 % of pixels are valid.
- STURM-Flood: classes 1–5 = water (1 flooded, 2 rivers/riverbanks/streams, 3 open water, 4 reservoirs, 5 lakes), 0 = land, 99 and NaN-support pixels ignored. Evaluated at 512 px (paper geometry) and at native 128 px (secondary).
- Sen1Floods11 test and Bolivia (official event-held-out split): hand labels as distributed.

**Secondary mappings from the same predictions:** WF flood-only (current P3, JRC permanent ignored, 785 windows); STURM paper (1–2 water, 3–5 ignored, = P3), strict flood (1 only) and paper-legacy (no NaN-support mask). The P3 mappings must reproduce `prompt5_closure/tables/current_full_summary.csv` and serve as the regression check.

**Approaches (113 models, `models.json`, SHA-256 checked at load):** frozen Prithvi teacher; the 44 recovered original N = 2,500 runs (paper student and the matched B0 / MobileNetV3 / LightFormer controls); the 40 Table I N = 252 arms and 4 ReLU6 N = 2,500 runs of the September reproduction (`runs_repro`); 24 capacity-ladder models (R4, A0, A3, A3N). LightFormer cannot run at 128 px and is excluded there only.

**Threshold-based baselines:** MNDWI, NDWI (B3/B8A), AWEInsh, AWEIsh, WI2015 at the published threshold 0, and at one threshold per rule calibrated on Sen1Floods11 train + validation only (maximum pooled water IoU; `results/calibration.json`, written before any test image is read). Learned models: argmax, plus an operating point selected on S11 validation only (from margin histograms). Test-set threshold sweeps are reported only as oracle diagnostics.

**Outputs:** `results/<dataset>.npz` (per-window TP/FP/FN/TN for every model × mapping, per-event margin/index histograms), `results/eval.log`; `collect.py` → `tables/` (pooled, per event, paired vs MNDWI with event bootstrap and Wilcoxon, AP and precision at MNDWI recall, dry windows, operating points). Events are the replication unit; seeds are averaged per event first.

**Scheduling:** `gpu_wait_run.py` (detached) waits until one GPU is exclusively idle (no compute process, utilization < 5 %, ≥ 16 GiB free, three observations over ≥ 29 s), takes the shared lock `/data1/schmalstieg/flooddistill/revision_gpu_<uuid>.lock` (the same one V9/V10 use) and holds it for the run. Running jobs are never touched. Status: `state.json`. Abort while waiting: `touch STOP`. Abort a running evaluation: `kill <child_pid from state.json>`; completed datasets are kept and skipped on restart.

**Loader default (15 Oct 2026, approved by the author).** `data/ood_datasets.py` (and its Jetson copy `jetson_repro/data/ood_datasets.py`) now takes `protocol=`, default `"surface_water"`: WF flood + permanent water = water with zero-padded edge windows (836 windows at 512), STURM classes 1–5 = water with the finite-support mask. `"flood_p3"` gives the revision P3 masks, `"flood_paper"` the submitted paper's (resized WF edge windows, no STURM support mask). The old keyword arguments (`ignore_permanent_water`, `permanent_water_as`, `class_mapping`) still select the old behaviour exactly. Scripts that regenerate submitted-paper tables or figures (`eval_ablations`, `eval_teacher_ood`, `disagreement_audit`, `quantize`, `figures/*`, the Jetson figure scripts) are pinned to `"flood_paper"`; `ood_eval.py` and `jetson/eval_jetson.py` (`--protocol`, default `surface_water`) follow the default. `check_loader_protocols.py` → `loader_protocol_check.json` verifies that the default and `flood_p3` reproduce, item by item, the inputs and masks this evaluation scored (WF 836 windows, STURM 2,675 chips at 512 and 128 px), and that the old keyword arguments give byte-identical items to the loader before the change.
